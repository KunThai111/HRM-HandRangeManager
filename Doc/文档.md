# NLH Range — 德州扑克范围记录工具（MVP）

## 1. 产品目标

提供一个轻量的网页工具，让用户在 **13×13 起手牌表** 上手动标注每一手牌的动作（弃 / 跟 / 加注），并把标注好的范围**命名保存到本地**。每个范围内部按 **筹码深度（Stack Size）** 维护多张子表（如 `100bb / 60bb / 40bb / 30bb / 20bb`），且深度标签**按范围独立可自定义**。

> **术语约定（贯穿全文与代码）**
> - **范围表**：固定结构的 **13×13 起手牌表**（169 格），是所有涂色操作的载体。后文与代码中提到的「网格」「子网格」「子表」一律对应同一概念。
> - **范围（RangeDoc）**：用户命名保存的一份方案，内部包含一个或多个深度，每个深度都拥有一份独立的范围表（即「深度子表」）。
> - **范围表 item**：范围表中的单个起手牌单元格（如 `AKs`、`QQ`、`T9o`），共 169 个，**默认背景色为白色**（即 Fold 状态）。

> MVP 不包含：位置/场景管理、混合频率、Equity 计算、云同步。这些放在「后续扩展」中。

---

## 2. 用户故事

- 作为一名德州玩家，我打开网页就能看到一张标准的 **范围表（13×13 起手牌表）**，所有 item 默认底色为白色。
- 左侧栏分上下两段（**都是竖排**）：
  - 上段：所有已保存范围（如 `BTN RFI`、`CO RFI`、`UTG RFI`），底部有 `+ 新建` 按钮。
  - 下段：当前激活范围下的**深度 tab 列表**（如 `100bb / 60bb / 40bb / 30bb / 20bb`），底部有 `⚙ 编辑深度` 按钮。
- 新建一个范围时，自动用全局"默认深度模板"为它生成多张空白的深度子表（默认 5 张：`100bb / 60bb / 40bb / 30bb / 20bb`）。
- 我可以在 `⚙ 编辑深度` 里给**当前范围**增/删/改/排序深度标签（不影响其他范围）。
- 我可以选择当前要涂的「动作颜色」（Raise / Call / Fold / Mixed），点击或拖动鼠标在范围表的 item 上刷颜色。
- 切换深度 tab → 立即切换显示该深度对应的范围表；切换范围 → 深度 tab 列表与范围表同步更新为该范围的内容。
- 关闭浏览器再打开，所有范围（含每个范围的深度集合与对应的范围表）依然在；自动恢复上次打开的范围与深度。

## 3. 功能清单（MVP）

### 3.1 范围表（13×13 起手牌表）

**定义**：本文与代码中所称「范围表」即固定结构的 13×13 起手牌表，是所有涂色操作的承载对象。每张范围表共 **169 个 item**（单元格），结构如下：

- 行 = 第一张牌点数（A, K, Q, ..., 2，从上到下递减）
- 列 = 第二张牌点数（同上，从左到右递减）
- item 命名规则（标准约定）：
  - 对角线：`AA`、`KK` … `22`（共 13 个对子）
  - 对角线**右上方**：同花（`s`），如 `AKs`、`AQs`（共 78 个）
  - 对角线**左下方**：非同花（`o`），如 `AKo`、`AQo`（共 78 个）
- 每个 item 显示牌面文本（如 `AKs`）和当前动作色。

**item 默认样式**：
- **默认背景色（Fold 状态）：白色 `#ffffff`**
- 默认文字颜色：深色 `#1f1f1f`（保证白底可读性）
- 仅当被涂为 Raise / Call / Mixed 时切换为对应动作色（见 §3.2）

**深度子表**：当某个范围拥有多个深度时，每个深度各自持有一张独立的范围表数据（互不干扰），统称「深度子表」。

### 3.2 涂色与动作
- 工具栏提供 **4 个动作**（颜色固定，MVP 不可自定义）：
  - `Raise`（红 `#dc3545`）
  - `Call`（绿 `#28a745`）
  - `Fold`（白 `#ffffff`，即范围表 item 的默认背景色，等价于"清除"）
  - `Mixed/Other`（黄 `#f4c542`，先打个标记，频率扇形留到后续）
- 交互：
  - **左键单击** item → 涂上当前动作色 ⚠️ 仅编辑模式下生效，见 §3.8
  - **左键按住拖动** → 连续涂色（刷子模式）⚠️ 仅编辑模式下生效
  - **右键单击** → 重置该 item 为 `Fold`（恢复白色默认背景）⚠️ 仅编辑模式下生效
  - 工具栏「全部清空」按钮 → 整张范围表全部置为 `Fold`（不受编辑模式限制）
  - 工具栏「全部 Raise」、「全部 Call」快捷按钮（方便先全选再剔除，不受编辑模式限制）
- **作用范围**：所有涂色操作只影响当前激活的「深度子表」，不会牵连其他深度。
- **编辑权限**：13×13 网格本身的「单格涂色 / 拖动刷涂 / 右键清除」三类操作只有在编辑模式开启时才允许，非编辑模式下网格只读。动作色选择、`全部清空 / 全部 Raise / 全部 Call` 三个工具栏快捷按钮**不受编辑模式限制**，任何时候都可点击。详见 §3.8。

### 3.3 左侧栏（竖排两段）

#### 上段：范围列表
- 列出所有已保存范围（按更新时间倒序），每项显示：名称 + 更新时间 + 当前深度数量徽标（如 `BTN RFI · 5d`）
- 当前激活范围高亮
- 列表项右键/悬浮菜单：重命名、复制（复制时连同所有深度子表一起复制）、删除
- 底部固定按钮：`+ 新建` → 弹窗输入名称 → 用全局默认深度模板生成多张空白的深度子表

#### 下段：当前范围的深度 tab 列表
- 仅当激活了某个范围时显示；没有激活范围则提示「先选择或新建一个范围」
- 竖排 pill 按钮列表，自上而下显示该范围内的所有深度标签（顺序可自定义）
- 当前深度高亮
- 标签右侧显示该深度的命中数（非 Fold 数 / 169，例如 `100bb · 23/169`）
- 底部固定按钮：`⚙ 编辑深度` → 打开深度编辑弹窗（见 3.5）

### 3.4 范围保存与管理
- 顶部输入框：当前范围名称（默认 `Untitled`）
- 按钮：`保存`、`另存为`、`删除`
- 切换范围/深度时若有未保存改动 → 弹确认
- "另存为"会克隆当前范围的全部深度子表

### 3.5 深度编辑弹窗
对**当前范围**的深度集合进行管理（不影响其他范围）：
- 列表项支持：拖拽排序、内联重命名、删除（删除会丢失该深度的范围表数据，需二次确认）
- 底部 `+ 添加深度`：输入新标签 → 追加到末尾，附带一张全 Fold（白底）的空白范围表
- 底部辅助：`将本范围的深度集合保存为默认模板`（写入全局 `defaultDepthLabels`，后续新建范围用它）
- `应用`、`取消` 按钮

### 3.6 全局默认深度模板
- 一个全局有序列表，决定**新建范围时**自动创建哪些深度子表
- 出厂值：`['100bb', '60bb', '40bb', '30bb', '20bb']`
- 可通过 3.5 节的「保存为默认模板」更新

### 3.7 数据持久化
- 全部保存在浏览器 `localStorage`
- 顶层 key：`nlh-range:v2`，值为 JSON
- 不依赖任何后端
- 额外保存 `lastOpenedRangeId` 与 `lastOpenedDepthLabel`，下次打开自动恢复

### 3.8 编辑模式（范围表只读 / 可写切换）

> ⚠️ 本节描述的「编辑」按钮**只控制 13×13 范围表能否被涂色**，与左侧栏下段底部的「⚙ 编辑深度」（用于增删改深度标签）是两个完全独立的功能，不要混淆。

**目的**：避免在浏览/对照范围时误触改色，需要显式进入编辑模式才能修改网格。

**按钮位置**：范围表正下方的「统计行」最左侧，与 `Raise / Call / Fold` 百分比同一行。

**两种状态**：

- **只读模式（默认）**：
  - 显示一颗按钮：`[✎ 编辑]`
  - 13×13 网格的鼠标左键单击、左键拖动、右键单击全部**禁用**（光标可改为 `not-allowed` 或保持默认，但不触发任何 store 写入）
  - 视觉上仍正常显示当前深度的范围表配色（不要灰化、不要遮罩，保证浏览体验）
  - 动作色选择（Raise / Call / Fold / Mixed）按钮、`全部清空 / 全部 Raise / 全部 Call` 仍**可点击**

- **编辑模式**：
  - 显示两颗按钮并排：`[✓ 确定]` `[✕ 取消]`
  - 13×13 网格恢复全部交互（单击 / 拖动 / 右键清除），见 §3.2
  - 顶部范围名旁的未保存标记 `•` 会按实际 dirty 状态显示

**状态切换规则**：

| 触发 | 行为 |
|---|---|
| 在只读模式下点击 `✎ 编辑` | 立即拍下当前激活深度子表的 `cells` 快照（用于后续取消回滚），切到编辑模式 |
| 在编辑模式下点击 `✓ 确定` | 仅退出编辑模式；本次编辑产生的涂色结果**保留在 draft 中**；顶部仍按需显示未保存 `•`；**不会**自动写入 localStorage，仍需用户点顶部「保存」才真正落盘 |
| 在编辑模式下点击 `✕ 取消` | 把之前拍下的快照写回当前深度的 `cells`，回滚到点击「编辑」之前的状态；同时退出编辑模式；如果本次会话内 dirty 仅由这次编辑造成，dirty 状态也应随之清除 |
| 在编辑模式下切换深度 tab | 视同自动按「取消」处理：先回滚本次编辑改动，再执行深度切换 |
| 在编辑模式下切换左侧范围 | 视同自动按「取消」处理：先回滚本次编辑改动，再执行范围切换 |
| 在编辑模式下打开「⚙ 编辑深度」弹窗 | 视同自动按「取消」处理，再打开弹窗 |
| 在编辑模式下点击顶部「保存 / 另存为 / 删除」 | 视同自动按「确定」处理（先退出编辑模式、保留涂色），再执行原操作 |
| 在没有激活范围 / 没有激活深度时 | `✎ 编辑` 按钮置灰禁用（与现有「先选择或新建一个范围」占位语义一致） |

**快捷键（可选，不强制 MVP 实现）**：
- `E` → 进入编辑模式
- `Enter` → 确定
- `Esc` → 取消

**实现提示**：
- 在 `useRangeStore` 的 draft 状态里新增两个字段：
  ```ts
  editing: boolean;                                  // 是否处于编辑模式
  editSnapshot: Record<string, Action> | null;       // 进入编辑模式时的 cells 快照（仅缓存当前激活深度的）
  ```
- 仅在 `editing === true` 时 `RangeGrid` 才把 `onPointerDown / onPointerEnter / onContextMenu` 真正应用到 store；否则 early return。
- 「取消」回滚时只回滚 `editSnapshot` 对应的那一份深度子表，**不影响**本次进入编辑模式之前用户已经在其他深度上做过的改动。
- 「全部清空 / 全部 Raise / 全部 Call」三个按钮虽然不受编辑模式限制，但仍计入 dirty 标记。

## 4. 数据模型

```ts
type Action = 'fold' | 'call' | 'raise' | 'mixed';

interface DepthGrid {
  label: string;                       // 深度标签，如 "100bb"，可自定义
  cells: Record<string, Action>;       // 169 格的动作映射，key 形如 "AKs"/"QQ"/"T9o"
}

interface RangeDoc {
  id: string;            // uuid
  name: string;          // 用户命名，如 "BTN RFI"
  depths: DepthGrid[];   // 每个 range 自己的深度集合，数组顺序 = UI 显示顺序
  createdAt: number;     // 时间戳 ms
  updatedAt: number;
}

interface Storage {
  version: 2;
  defaultDepthLabels: string[];        // 新建 range 时的模板
  ranges: RangeDoc[];
  lastOpenedRangeId: string | null;
  lastOpenedDepthLabel: string | null;
}
```

### 4.1 单元格 key 生成规则
- 输入两张牌点数 `r1`, `r2`（按强度排序，强者在前）
- `r1 === r2` → `"AA"` / `"KK"` …
- 行号 < 列号（右上）→ `"${r1}${r2}s"`（同花）
- 行号 > 列号（左下）→ `"${r1}${r2}o"`（非同花）

牌点字符顺序常量：`['A','K','Q','J','T','9','8','7','6','5','4','3','2']`

### 4.2 标签唯一性
- 同一 range 内深度标签必须唯一（区分大小写敏感的字符串比较）
- 重命名/添加时若冲突 → 提示并阻止保存

### 4.3 数据迁移
- 若读取到 `nlh-range:v1`（旧扁平结构 `RangeDoc { stack, cells }`）→ 按 `stack` 字段把同名/同 id 的合并到新 `RangeDoc.depths` 中
- MVP 阶段无 v1 数据，迁移函数仅留占位

## 7. 关键交互细节

### 7.1 拖动涂色
- 在 `RangeGrid`（范围表组件）上监听 `pointerdown` / `pointerenter` / `pointerup`
- `pointerdown` 时记录 `isPainting=true` 与起始动作色
- `pointerenter` item 时若 `isPainting` 为真，则应用当前动作色到**当前激活深度**的范围表
- `pointerup` / 容器 `pointerleave` → `isPainting=false`

### 7.2 范围/深度切换
- 切换深度（点击 `DepthList` 中的 tab）：
  - 若当前范围表有未保存改动 → 弹确认（保存 / 放弃 / 取消）
  - 否则立即切换 `lastOpenedDepthLabel` 并重新渲染范围表
- 切换范围（点击 `RangeList` 中的项）：
  - 同样未保存改动 → 弹确认
  - 切换后默认激活该范围 `depths[0]`，并写入 `lastOpenedDepthLabel`

### 7.3 新建范围
- 点 `+ 新建` → 弹窗输入名称（必填，可重名但建议不重名）
- 提交 → 用 `Storage.defaultDepthLabels` 复制生成 `depths`，每个 `cells` 全为 `fold`
- 立即激活新范围与其第一个深度

### 7.4 深度编辑（⚙ 编辑深度）
- 弹窗内列出当前范围的 `depths`（拖拽排序、内联改名、删除）
- 删除：弹二次确认（提示该深度的所有标记会丢失）
- 添加：底部输入框 + `+ 添加`，新深度的 `cells` 初始化为全 `fold`
- 重命名时校验同 range 内唯一性
- 底部勾选框「同时保存为新建范围的默认模板」
- 「应用」前所有修改是缓存态，「取消」直接丢弃

### 7.5 编辑模式切换（统计行的 `✎ 编辑 / ✓ 确定 / ✕ 取消`）

> 详细规则与按钮表格见 §3.8，这里只描述实现层面的事件序列。

- 进入编辑模式：
  - 仅在「已有激活范围 + 已有激活深度」时按钮可点击
  - 点击后立刻把 `draft.depths[currentDepthLabel].cells` 做一次浅拷贝存为 `draft.editSnapshot`
  - `draft.editing = true`，UI 上 `✎ 编辑` 被替换为 `✓ 确定` + `✕ 取消`
- 编辑模式下涂色：
  - `RangeGrid` 的 `onPointerDown / onPointerEnter / onContextMenu` 检查 `draft.editing`，否则 early return
  - 涂色仍然走原有的 `rangeActions.paintCell(hand, action)`，正常写 draft + 标 dirty
- 确定：
  - `draft.editing = false`，`draft.editSnapshot = null`
  - **不**触发持久化；dirty 标记按实际差异决定（如果本次编辑确实改动了 cells，则保留 `•`）
- 取消：
  - 把 `draft.editSnapshot` 写回 `draft.depths[currentDepthLabel].cells`
  - `draft.editing = false`，`draft.editSnapshot = null`
  - 重新对比 draft 与 localStorage 中保存的版本，更新 dirty 标记（若本次编辑是唯一改动来源，dirty 应回到 false）
- 联动：
  - 切换深度 / 切换范围 / 打开「⚙ 编辑深度」弹窗 → 内部先调用「取消」逻辑再执行原跳转
  - 点击顶部「保存 / 另存为 / 删除」→ 内部先调用「确定」逻辑再执行原操作

### 7.6 自动保存与显式保存
- 有"未保存修改"标识（顶部名称旁的 `•`）
- MVP 不做后台自动保存，避免覆盖意外操作
- "保存"会写入当前范围的全部 `depths`（不只是当前激活的深度子表）

### 7.7 统计
- Raise / 169、Call / 169、Fold / 169（基于**当前激活深度**的范围表）
- 数字按百分比显示，1 位小数

## 8. 验收标准（MVP 完成定义）

1. 打开页面看到完整的范围表（13×13），所有 item 默认 **Fold（白底）**；左侧栏分上下两段；尚未新建范围时下段提示「先选择或新建一个范围」。
2. 点 `+ 新建` 输入 `BTN RFI` 保存 → 上段出现该项；下段自动出现 5 个深度 pill（`100bb / 60bb / 40bb / 30bb / 20bb`），默认激活第一个。
3. 选中 Raise，在 `100bb` 涂红若干 item → 切到 `60bb` 时范围表全为白底，确认数据互不干扰；切回 `100bb` 红色仍在。
4. 在 `⚙ 编辑深度` 里把 `60bb` 改名为 `50bb`、删除 `20bb`、新增 `8bb`，应用后下段 pill 列表与排序与编辑结果一致。
5. 输入名称 `CO RFI` 用 `+ 新建` 创建第二个范围 → 它的深度集合仍是默认模板（不受 `BTN RFI` 第 4 步修改影响），符合"每个 range 独立"的要求。
6. 在深度编辑弹窗勾选「同时保存为新建范围的默认模板」并应用 → 之后再 `+ 新建` 的范围会用更新后的模板。
7. 刷新页面：范围列表、各范围的深度集合、各深度子表内容全部一致；自动恢复到上次激活的范围与深度。
8. 删除某个范围后再刷新，确认已删除。
9. 底部统计与当前激活深度的实际涂色数字一致。
10. 在 1280×800 与 375×667（手机）两种尺寸下都可正常使用，移动端左侧栏可折叠。
11. 默认进入页面时统计行显示 `✎ 编辑` 单按钮，此时左键点格、左键拖动、右键单击均**不会**改变网格颜色；点击 `✎ 编辑` 后按钮变为 `✓ 确定` + `✕ 取消`，再涂色生效；点 `✕ 取消` 回到点击 `✎ 编辑` 前的网格状态；点 `✓ 确定` 保留涂色但**不**自动落盘（顶部仍显示未保存 `•`，仍需手动「保存」）；在编辑模式下切换深度或范围时本次编辑会被自动取消。
