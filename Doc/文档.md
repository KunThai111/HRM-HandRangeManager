# NLH Range — 德州扑克范围记录工具（MVP）

## 1. 产品目标

提供一个轻量的网页工具，让用户在 **13×13 起手牌网格** 上手动标注每一手牌的动作（弃 / 跟 / 加注），并把标注好的范围**命名保存到本地**。每个范围内部按 **筹码深度（Stack Size）** 维护多张子网格（如 `100bb / 60bb / 40bb / 30bb / 20bb`），且深度标签**按范围独立可自定义**。

> MVP 不包含：位置/场景管理、混合频率、Equity 计算、云同步。这些放在「后续扩展」中。

---

## 2. 用户故事

- 作为一名德州玩家，我打开网页就能看到一个标准的 13×13 起手牌网格。
- 左侧栏分上下两段（**都是竖排**）：
  - 上段：所有已保存范围（如 `BTN RFI`、`CO RFI`、`UTG RFI`），底部有 `+ 新建` 按钮。
  - 下段：当前激活范围下的**深度 tab 列表**（如 `100bb / 60bb / 40bb / 30bb / 20bb`），底部有 `⚙ 编辑深度` 按钮。
- 新建一个范围时，自动用全局"默认深度模板"为它生成多张空白子网格（默认 5 张：`100bb / 60bb / 40bb / 30bb / 20bb`）。
- 我可以在 `⚙ 编辑深度` 里给**当前范围**增/删/改/排序深度标签（不影响其他范围）。
- 我可以选择当前要涂的「动作颜色」（Raise / Call / Fold / Mixed），点击或拖动鼠标在格子上刷颜色。
- 切换深度 tab → 立即切换显示该深度对应的子网格；切换范围 → 深度 tab 列表与网格同步更新为该范围的内容。
- 关闭浏览器再打开，所有范围（含每个范围的深度集合与子网格）依然在；自动恢复上次打开的范围与深度。

## 3. 功能清单（MVP）

### 3.1 13×13 起手牌网格
- 行 = 第一张牌点数（A, K, Q, ..., 2，从上到下递减）
- 列 = 第二张牌点数（同上，从左到右递减）
- 单元格命名规则（标准约定）：
  - 对角线：`AA`、`KK` … `22`（共 13 个对子）
  - 对角线**右上方**：同花（`s`），如 `AKs`、`AQs`（共 78 个）
  - 对角线**左下方**：非同花（`o`），如 `AKo`、`AQo`（共 78 个）
- 共 169 个单元格，每个单元格显示牌面文本（如 `AKs`）和当前动作色。

### 3.2 涂色与动作
- 工具栏提供 **4 个动作**（颜色固定，MVP 不可自定义）：
  - `Raise`（红）
  - `Call`（绿）
  - `Fold`（灰，等价于"清除"）
  - `Mixed/Other`（黄，先打个标记，频率扇形留到后续）
- 交互：
  - **左键单击**单元格 → 涂上当前动作色
  - **左键按住拖动** → 连续涂色（刷子模式）
  - **右键单击** → 重置该格为 `Fold`
  - 工具栏「全部清空」按钮 → 全部置为 `Fold`
  - 工具栏「全部 Raise」、「全部 Call」快捷按钮（方便先全选再剔除）
- **作用范围**：所有涂色操作只影响当前激活的"深度子网格"，不会牵连其他深度。

### 3.3 左侧栏（竖排两段）

#### 上段：范围列表
- 列出所有已保存范围（按更新时间倒序），每项显示：名称 + 更新时间 + 当前深度数量徽标（如 `BTN RFI · 5d`）
- 当前激活范围高亮
- 列表项右键/悬浮菜单：重命名、复制（复制时连同所有子网格一起复制）、删除
- 底部固定按钮：`+ 新建` → 弹窗输入名称 → 用全局默认深度模板生成多张空白子网格

#### 下段：当前范围的深度 tab 列表
- 仅当激活了某个范围时显示；没有激活范围则提示「先选择或新建一个范围」
- 竖排 pill 按钮列表，自上而下显示该范围内的所有深度标签（顺序可自定义）
- 当前深度高亮
- 标签右侧显示该深度的命中数（非 Fold 数 / 169，例如 `100bb · 23/169`）
- 底部固定按钮：`⚙ 编辑深度` → 打开深度编辑弹窗（见 3.5）

### 3.4 范围保存与管理
- 顶部输入框：当前范围名称（默认 `Untitled`）
- 按钮：`保存`、`另存为`、`删除`
- 切换范围/深度时若有未保存改动 → 弹确认
- "另存为"会克隆当前范围的全部深度子网格

### 3.5 深度编辑弹窗
对**当前范围**的深度集合进行管理（不影响其他范围）：
- 列表项支持：拖拽排序、内联重命名、删除（删除会丢失该深度的子网格数据，需二次确认）
- 底部 `+ 添加深度`：输入新标签 → 追加到末尾，附带一张全 Fold 的空白子网格
- 底部辅助：`将本范围的深度集合保存为默认模板`（写入全局 `defaultDepthLabels`，后续新建范围用它）
- `应用`、`取消` 按钮

### 3.6 全局默认深度模板
- 一个全局有序列表，决定**新建范围时**自动创建哪些深度子网格
- 出厂值：`['100bb', '60bb', '40bb', '30bb', '20bb']`
- 可通过 3.5 节的「保存为默认模板」更新

### 3.7 数据持久化
- 全部保存在浏览器 `localStorage`
- 顶层 key：`nlh-range:v2`，值为 JSON
- 不依赖任何后端
- 额外保存 `lastOpenedRangeId` 与 `lastOpenedDepthLabel`，下次打开自动恢复

## 4. 数据模型

```ts
type Action = 'fold' | 'call' | 'raise' | 'mixed';

interface DepthGrid {
  label: string;                       // 深度标签，如 "100bb"，可自定义
  cells: Record<string, Action>;       // 169 格的动作映射，key 形如 "AKs"/"QQ"/"T9o"
}

interface RangeDoc {
  id: string;            // uuid
  name: string;          // 用户命名，如 "BTN RFI"
  depths: DepthGrid[];   // 每个 range 自己的深度集合，数组顺序 = UI 显示顺序
  createdAt: number;     // 时间戳 ms
  updatedAt: number;
}

interface Storage {
  version: 2;
  defaultDepthLabels: string[];        // 新建 range 时的模板
  ranges: RangeDoc[];
  lastOpenedRangeId: string | null;
  lastOpenedDepthLabel: string | null;
}
```

### 4.1 单元格 key 生成规则
- 输入两张牌点数 `r1`, `r2`（按强度排序，强者在前）
- `r1 === r2` → `"AA"` / `"KK"` …
- 行号 < 列号（右上）→ `"${r1}${r2}s"`（同花）
- 行号 > 列号（左下）→ `"${r1}${r2}o"`（非同花）

牌点字符顺序常量：`['A','K','Q','J','T','9','8','7','6','5','4','3','2']`

### 4.2 标签唯一性
- 同一 range 内深度标签必须唯一（区分大小写敏感的字符串比较）
- 重命名/添加时若冲突 → 提示并阻止保存

### 4.3 数据迁移
- 若读取到 `nlh-range:v1`（旧扁平结构 `RangeDoc { stack, cells }`）→ 按 `stack` 字段把同名/同 id 的合并到新 `RangeDoc.depths` 中
- MVP 阶段无 v1 数据，迁移函数仅留占位

## 6. 技术栈

- **框架**：React 18 + TypeScript
- **构建**：Vite
- **样式**：CSS Modules（保持轻量，无需 Tailwind/UI 库）
- **状态**：React `useState` / `useReducer` + 一个轻量 store hook（`useRangeStore`，基于 `useSyncExternalStore`），无需 Redux
- **存储**：浏览器原生 `localStorage`
- **测试**：MVP 不强制；保留 Vitest 入口
- **包管理**：npm

## 7. 关键交互细节

### 7.1 拖动涂色
- 在 `RangeGrid` 上监听 `pointerdown` / `pointerenter` / `pointerup`
- `pointerdown` 时记录 `isPainting=true` 与起始动作色
- `pointerenter` 单元格时若 `isPainting` 为真，则应用当前动作色到**当前激活深度**的子网格
- `pointerup` / 容器 `pointerleave` → `isPainting=false`

### 7.2 范围/深度切换
- 切换深度（点击 `DepthList` 中的 tab）：
  - 若当前子网格有未保存改动 → 弹确认（保存 / 放弃 / 取消）
  - 否则立即切换 `lastOpenedDepthLabel` 并重新渲染网格
- 切换范围（点击 `RangeList` 中的项）：
  - 同样未保存改动 → 弹确认
  - 切换后默认激活该范围 `depths[0]`，并写入 `lastOpenedDepthLabel`

### 7.3 新建范围
- 点 `+ 新建` → 弹窗输入名称（必填，可重名但建议不重名）
- 提交 → 用 `Storage.defaultDepthLabels` 复制生成 `depths`，每个 `cells` 全为 `fold`
- 立即激活新范围与其第一个深度

### 7.4 深度编辑（⚙ 编辑深度）
- 弹窗内列出当前范围的 `depths`（拖拽排序、内联改名、删除）
- 删除：弹二次确认（提示该深度的所有标记会丢失）
- 添加：底部输入框 + `+ 添加`，新深度的 `cells` 初始化为全 `fold`
- 重命名时校验同 range 内唯一性
- 底部勾选框「同时保存为新建范围的默认模板」
- 「应用」前所有修改是缓存态，「取消」直接丢弃

### 7.5 自动保存与显式保存
- 有"未保存修改"标识（顶部名称旁的 `•`）
- MVP 不做后台自动保存，避免覆盖意外操作
- "保存"会写入当前范围的全部 `depths`（不只是当前激活的子网格）

### 7.6 统计
- Raise / 169、Call / 169、Fold / 169（基于**当前激活深度**子网格）
- 数字按百分比显示，1 位小数

## 8. 验收标准（MVP 完成定义）

1. 打开页面看到完整 13×13 网格，所有格子默认 Fold（灰）；左侧栏分上下两段；尚未新建范围时下段提示「先选择或新建一个范围」。
2. 点 `+ 新建` 输入 `BTN RFI` 保存 → 上段出现该项；下段自动出现 5 个深度 pill（`100bb / 60bb / 40bb / 30bb / 20bb`），默认激活第一个。
3. 选中 Raise，在 `100bb` 涂红若干格 → 切到 `60bb` 网格全为灰，确认数据互不干扰；切回 `100bb` 红色仍在。
4. 在 `⚙ 编辑深度` 里把 `60bb` 改名为 `50bb`、删除 `20bb`、新增 `8bb`，应用后下段 pill 列表与排序与编辑结果一致。
5. 输入名称 `CO RFI` 用 `+ 新建` 创建第二个范围 → 它的深度集合仍是默认模板（不受 `BTN RFI` 第 4 步修改影响），符合"每个 range 独立"的要求。
6. 在深度编辑弹窗勾选「同时保存为新建范围的默认模板」并应用 → 之后再 `+ 新建` 的范围会用更新后的模板。
7. 刷新页面：范围列表、各范围的深度集合、各深度子网格内容全部一致；自动恢复到上次激活的范围与深度。
8. 删除某个范围后再刷新，确认已删除。
9. 底部统计与当前激活深度的实际涂色数字一致。
10. 在 1280×800 与 375×667（手机）两种尺寸下都可正常使用，移动端左侧栏可折叠。

## 9. 后续可扩展（非 MVP）

- 跨范围复制深度（把 A 的 `100bb` 复制为 B 的 `100bb`）
- 范围对比（A.100bb ∩ B.100bb 高亮）
- 混合频率（每格分扇形显示比例）
- 位置/场景标签（UTG/MP/CO/BTN/SB/BB × RFI/vs3bet/...）
- 导入 / 导出 JSON、PNG 图片
- 与 PIO / GTO+ 兼容的格式
- 简单 Equity 计算（蒙特卡洛 vs 范围）
- 云端同步（账户体系）
- 暗色 / 亮色主题切换、自定义动作颜色
- 全局深度模板的多套预设（如 「现金 6max」「MTT 巡回」分别一套默认）

## 10. 里程碑（MVP 实施步骤）

1. **脚手架**：Vite + React + TS 初始化，跑通空白页
2. **核心组件**：`hands.ts` 生成 169 key + `RangeGrid` 渲染 + 默认 Fold 配色
3. **涂色交互**：`ActionToolbar` + 单击/拖动涂色 + 右键清除
4. **存储层**：`storage.ts` + `useRangeStore`（含 `defaultDepthLabels` 与按 range/depth 寻址的增删改查）
5. **左侧栏上段**：`RangeList` + `+ 新建`（自动用模板生成 depths）
6. **左侧栏下段**：`DepthList` + 切换深度联动网格
7. **深度编辑弹窗**：`DepthEditorDialog`（拖拽排序、改名、增删、保存为默认模板）
8. **未保存提示与持久化恢复**：`lastOpenedRangeId` / `lastOpenedDepthLabel`
9. **统计与样式打磨**：`Stats` + 暗色主题 + 移动端左侧栏折叠
10. **手测验收**：按第 8 节逐条勾选
