# NLH Range — 德州扑克范围记录工具（MVP）

## 1. 产品目标

提供一个轻量的网页工具，让用户在 **13×13 起手牌表** 上手动标注每一手牌的动作（弃 / 跟 / 加注），并把标注好的范围**命名保存到本地**。每个范围内部按 **筹码深度（Stack Size）** × **座位（Position）** 双维度维护多张子表：例如 `100bb / 60bb / 40bb / 30bb / 20bb` 各深度下，再按 `UTG / U1 / U2 / LJ / HJ / CO / BTN / SB / BB` 拆出该桌人数对应的若干张范围表。深度标签**按范围独立可自定义**；座位列表由该范围创建时选定的人数决定。

> **术语约定（贯穿全文与代码）**
> - **范围表**：固定结构的 **13×13 起手牌表**（169 格），是所有涂色操作的载体。后文与代码中提到的「网格」「子网格」「子表」一律对应同一概念。
> - **范围（RangeDoc）**：用户命名保存的一份方案，内部包含一个固定的桌子人数（`seats`，2–9）以及若干「深度」；每个深度下又按当前桌人数对应的座位序列拆分出若干张独立的范围表。
> - **座位（SeatId）**：位置标签，按从早位到晚位顺序为 `UTG / U1 / U2 / LJ / HJ / CO / BTN / SB / BB`（`U1`、`U2` 即 `UTG+1`、`UTG+2` 的简写）。具体桌子有哪些座位由 `seats` 数决定，详见 §3.9。
> - **范围表 item**：范围表中的单个起手牌单元格（如 `AKs`、`QQ`、`T9o`），共 169 个，**默认背景色为白色**（即 Fold 状态）。
> - **范围按钮区域**：紧贴范围表**右上角**的纵向工具栏（卡片式容器，顶端与范围表对齐），自上而下依次为 4 颗动作色按钮（`Fold / Call / Raise / Mixed`）→ 一道分隔线 → 3 颗快捷按钮（`全部清空 / 全部 Raise / 全部 Call`）。对应组件 `ActionToolbar` 的 `orientation="vertical"` 形态；交互行为见 §3.2、编辑权限见 §3.8。

> MVP 不包含：场景标签（vs3bet / vs4bet）、混合频率、Equity 计算、云同步。这些放在「后续扩展」中。

---

## 2. 用户故事

- 作为一名德州玩家，我打开网页就能看到一张标准的 **范围表（13×13 起手牌表）**，所有 item 默认底色为白色。
- 左侧栏分上下两段（**都是竖排**）：
  - 上段：所有已保存范围（如 `BTN RFI`、`CO RFI`、`UTG RFI`），底部有 `+ 新建` 按钮。
  - 下段：当前激活范围下的**深度 tab 列表**（如 `100bb / 60bb / 40bb / 30bb / 20bb`），底部有 `⚙ 编辑深度` 按钮。
- 新建一个范围时，自动用全局"默认深度模板"为它生成多张空白的深度子表（默认 5 张：`100bb / 60bb / 40bb / 30bb / 20bb`）。
- 我可以在 `⚙ 编辑深度` 里给**当前范围**增/删/改/排序深度标签（不影响其他范围）。
- 我可以选择当前要涂的「动作颜色」（Raise / Call / Fold / Mixed），点击或拖动鼠标在范围表的 item 上刷颜色。
- 切换深度 tab → 立即切换显示该深度对应的范围表；切换范围 → 深度 tab 列表与范围表同步更新为该范围的内容。
- 关闭浏览器再打开，所有范围（含每个范围的深度集合与对应的范围表）依然在；自动恢复上次打开的范围与深度。

## 3. 功能清单（MVP）

### 3.1 范围表（13×13 起手牌表）

**定义**：本文与代码中所称「范围表」即固定结构的 13×13 起手牌表，是所有涂色操作的承载对象。每张范围表共 **169 个 item**（单元格），结构如下：

- 行 = 第一张牌点数（A, K, Q, ..., 2，从上到下递减）
- 列 = 第二张牌点数（同上，从左到右递减）
- item 命名规则（标准约定）：
  - 对角线：`AA`、`KK` … `22`（共 13 个对子）
  - 对角线**右上方**：同花（`s`），如 `AKs`、`AQs`（共 78 个）
  - 对角线**左下方**：非同花（`o`），如 `AKo`、`AQo`（共 78 个）
- 每个 item 显示牌面文本（如 `AKs`）和当前动作色。

**item 默认样式**：
- **默认背景色（Fold 状态）：白色 `#ffffff`**
- 默认文字颜色：深色 `#1f1f1f`（保证白底可读性）
- 仅当被涂为 Raise / Call / Mixed 时切换为对应动作色（见 §3.2）

**深度 × 座位 × 对战座位 子表**：每个深度下并不是单一一张范围表，而是按当前桌人数对应的座位序列再拆分出多张独立的范围表数据（互不干扰）。同时每个 (深度, 英雄座位) 还可以再按「对战座位」做进一步细分（详见 §3.10）。整体存储结构是 `范围 → 深度 → 英雄座位 → { 总体范围 + 各对战座位独立范围 }`。任何涂色都只发生在「当前激活的 (深度, 英雄座位, 对战座位)」对应的那一张子表上；当对战座位没选具体值时，「当前激活」的就是该 (深度, 英雄座位) 的「总体范围」。

### 3.2 涂色与动作
- 工具栏提供 **4 个动作**（颜色固定，MVP 不可自定义）：
  - `Raise`（红 `#dc3545`）
  - `Call`（绿 `#28a745`）
  - `Fold`（白 `#ffffff`，即范围表 item 的默认背景色，等价于"清除"）
  - `Mixed/Other`（黄 `#f4c542`，先打个标记，频率扇形留到后续）
- 交互：
  - **左键单击** item → 涂上当前动作色 ⚠️ 仅编辑模式下生效，见 §3.8
  - **左键按住拖动** → 连续涂色（刷子模式）⚠️ 仅编辑模式下生效
  - **右键单击** → 重置该 item 为 `Fold`（恢复白色默认背景）⚠️ 仅编辑模式下生效
  - 工具栏「全部清空」按钮 → 整张范围表全部置为 `Fold`（不受编辑模式限制）
  - 工具栏「全部 Raise」、「全部 Call」快捷按钮（方便先全选再剔除，不受编辑模式限制）
- **作用范围**：所有涂色操作只影响当前激活的「(深度, 英雄座位, 对战座位) 子表」，不会牵连其他深度 / 其他英雄座位 / 其他对战座位。当「对战座位」未选具体值（即处于「总体」模式）时，涂色直接写到该 (深度, 英雄座位) 的总体范围；当选了具体对战座位时，按 §3.10 描述的 copy-on-write 规则写入该对战的独立范围。
- **编辑权限**：13×13 网格本身的「单格涂色 / 拖动刷涂 / 右键清除」三类操作只有在编辑模式开启时才允许，非编辑模式下网格只读。动作色选择、`全部清空 / 全部 Raise / 全部 Call` 三个工具栏快捷按钮**不受编辑模式限制**，任何时候都可点击。详见 §3.8。

### 3.3 左侧栏（竖排两段）

#### 上段：范围列表
- 列出所有已保存范围（按更新时间倒序），每项显示：名称 + 更新时间 + 当前深度数量徽标（如 `BTN RFI · 5d`）
- 当前激活范围高亮
- 列表项右键/悬浮菜单：重命名、复制（复制时连同所有深度子表一起复制）、删除
- 底部固定按钮：`+ 新建` → 弹窗输入名称 → 用全局默认深度模板生成多张空白的深度子表

#### 下段：当前范围的深度 tab 列表
- 仅当激活了某个范围时显示；没有激活范围则提示「先选择或新建一个范围」
- 竖排 pill 按钮列表，自上而下显示该范围内的所有深度标签（顺序可自定义）
- 当前深度高亮
- 标签右侧显示该深度的命中数（非 Fold 数 / 169，例如 `100bb · 23/169`）
- 底部固定按钮：`⚙ 编辑深度` → 打开深度编辑弹窗（见 3.5）

### 3.4 范围保存与管理
- 顶部输入框：当前范围名称（默认 `Untitled`）
- 按钮：`保存`、`另存为`、`删除`
- 切换范围/深度时若有未保存改动 → 弹确认
- "另存为"会克隆当前范围的全部深度子表

### 3.5 深度编辑弹窗
对**当前范围**的深度集合进行管理（不影响其他范围）：
- 列表项支持：拖拽排序、内联重命名、删除（删除会丢失该深度的范围表数据，需二次确认）
- 底部 `+ 添加深度`：输入新标签 → 追加到末尾，附带一张全 Fold（白底）的空白范围表
- 底部辅助：`将本范围的深度集合保存为默认模板`（写入全局 `defaultDepthLabels`，后续新建范围用它）
- `应用`、`取消` 按钮

### 3.6 全局默认深度模板
- 一个全局有序列表，决定**新建范围时**自动创建哪些深度子表
- 出厂值：`['100bb', '60bb', '40bb', '30bb', '20bb']`
- 可通过 3.5 节的「保存为默认模板」更新

### 3.7 数据持久化
- 全部保存在浏览器 `localStorage`
- 顶层 key：`nlh-range:v2`，值为 JSON
- 不依赖任何后端
- 额外保存 `lastOpenedRangeId` 与 `lastOpenedDepthLabel`，下次打开自动恢复

### 3.8 编辑模式（范围表只读 / 可写切换）

> ⚠️ 本节描述的「编辑」按钮**只控制 13×13 范围表能否被涂色**，与左侧栏下段底部的「⚙ 编辑深度」（用于增删改深度标签）是两个完全独立的功能，不要混淆。

**目的**：避免在浏览/对照范围时误触改色，需要显式进入编辑模式才能修改网格。

**按钮位置**：范围表正下方的「统计行」最左侧，与 `Raise / Call / Fold` 百分比同一行。

**两种状态**：

- **只读模式（默认）**：
  - 显示一颗按钮：`[✎ 编辑]`
  - 13×13 网格的鼠标左键单击、左键拖动、右键单击全部**禁用**（光标可改为 `not-allowed` 或保持默认，但不触发任何 store 写入）
  - 视觉上仍正常显示当前深度的范围表配色（不要灰化、不要遮罩，保证浏览体验）
  - 动作色选择（Raise / Call / Fold / Mixed）按钮、`全部清空 / 全部 Raise / 全部 Call` 仍**可点击**

- **编辑模式**：
  - 显示两颗按钮并排：`[✓ 确定]` `[✕ 取消]`
  - 13×13 网格恢复全部交互（单击 / 拖动 / 右键清除），见 §3.2
  - 顶部范围名旁的未保存标记 `•` 会按实际 dirty 状态显示

**状态切换规则**：

| 触发 | 行为 |
|---|---|
| 在只读模式下点击 `✎ 编辑` | 立即拍下当前激活深度子表的 `cells` 快照（用于后续取消回滚），切到编辑模式 |
| 在编辑模式下点击 `✓ 确定` | 仅退出编辑模式；本次编辑产生的涂色结果**保留在 draft 中**；顶部仍按需显示未保存 `•`；**不会**自动写入 localStorage，仍需用户点顶部「保存」才真正落盘 |
| 在编辑模式下点击 `✕ 取消` | 把之前拍下的快照写回当前深度的 `cells`，回滚到点击「编辑」之前的状态；同时退出编辑模式；如果本次会话内 dirty 仅由这次编辑造成，dirty 状态也应随之清除 |
| 在编辑模式下切换深度 tab | 视同自动按「取消」处理：先回滚本次编辑改动，再执行深度切换 |
| 在编辑模式下切换左侧范围 | 视同自动按「取消」处理：先回滚本次编辑改动，再执行范围切换 |
| 在编辑模式下打开「⚙ 编辑深度」弹窗 | 视同自动按「取消」处理，再打开弹窗 |
| 在编辑模式下点击顶部「保存 / 另存为 / 删除」 | 视同自动按「确定」处理（先退出编辑模式、保留涂色），再执行原操作 |
| 在没有激活范围 / 没有激活深度时 | `✎ 编辑` 按钮置灰禁用（与现有「先选择或新建一个范围」占位语义一致） |

**快捷键（可选，不强制 MVP 实现）**：
- `E` → 进入编辑模式
- `Enter` → 确定
- `Esc` → 取消

**实现提示**：
- 在 `useRangeStore` 的 draft 状态里新增字段：
  ```ts
  editing: boolean;        // 是否处于编辑模式
  editSnapshot: {           // 进入编辑模式时的 (depth, seat) 快照
    depthLabel: string;
    seatId: string;
    cells: Record<string, Action>;
  } | null;
  ```
- 仅在 `editing === true` 时 `RangeGrid` 才把 `onPointerDown / onPointerEnter / onContextMenu` 真正应用到 store；否则 early return。
- 「取消」回滚时只回滚 `editSnapshot` 对应的那一份 `(深度, 座位)` 子表，**不影响**本次进入编辑模式之前用户已经在其他深度或其他座位上做过的改动。
- 「全部清空 / 全部 Raise / 全部 Call」三个按钮虽然不受编辑模式限制，但仍计入 dirty 标记。

### 3.9 座位（Position）维度

**目的**：现实中同一种打法在不同位置的范围差别很大（UTG 比 BTN 紧很多）。为了让一个 RangeDoc 能完整描述某一玩法在所有位置上的范围表，引入第二维「座位」。

**座位序列**：固定常量，按从最早位到大盲位排列：
```
UTG  U1  U2  LJ  HJ  CO  BTN  SB  BB
```
其中 `U1` / `U2` 是 `UTG+1` / `UTG+2` 的简写，按钮上直接显示 `U1` / `U2`，鼠标悬浮时 tooltip 显示全称。

**按人数截断**：每个 RangeDoc 在创建时选定 2–9 人桌（`seats` 字段），实际呈现的座位列表是上述序列的子集，规则如下：

| 人数 | 座位序列 |
|---|---|
| 9 | `UTG · U1 · U2 · LJ · HJ · CO · BTN · SB · BB` |
| 8 | `UTG · U1 · LJ · HJ · CO · BTN · SB · BB` |
| 7 | `UTG · LJ · HJ · CO · BTN · SB · BB` |
| 6 | `UTG · HJ · CO · BTN · SB · BB` |
| 5 | `HJ · CO · BTN · SB · BB` |
| 4 | `CO · BTN · SB · BB` |
| 3 | `BTN · SB · BB` |
| 2 | `SB · BB` |

总规则：从 9 人开始，每减少 1 人就按 `U2 → U1 → LJ → UTG → HJ → CO` 的顺序去掉一个最早位（直到 2 人桌只剩 SB/BB）。

**UI 位置**：座位选择按钮**横排放在范围表的正上方**（在功能主区域顶部、左右动作工具栏之外）。每颗按钮显示座位 id（`UTG`、`U1`、`U2` 等），当前激活座位高亮；按钮上若该 (深度, 座位) 已有涂色，会附带一个小徽标显示命中数。

**与深度的关系**：座位列表与深度列表互相独立——左侧栏下段仍是「筹码深度」切换，顶部一行是「英雄座位」切换。任何时候视图渲染的是「当前深度 × 当前英雄座位 × 当前对战座位」对应的那一张范围表（详见 §3.10）。

**切换规则**（与 §3.8 编辑模式联动）：

| 触发 | 行为 |
|---|---|
| 在只读模式下点击其他英雄座位 | 直接切换 `currentSeatId` 并写入 `lastOpenedSeatId`；同时把 `currentOpponentId` 自动重置为 `null`（回到「总体」），因为对战是相对于英雄而言的 |
| 在编辑模式下点击其他英雄座位 | 视同自动按「取消」处理（只回滚当前 (深度, 英雄座位, 对战座位) 的本次编辑），再执行座位切换；切换后对战同样重置为「总体」 |
| 在「⚙ 编辑深度」里删除整个深度 | 该深度下所有英雄座位的范围表数据（含总体与各对战独立范围）一起丢失，需二次确认 |
| 修改当前范围的桌子人数（如有） | 若新人数对应的座位序列中不再包含 `currentSeatId`，自动回退到该序列首位（最早位）；若新序列不再包含 `currentOpponentId` 或它正好等于新的 `currentSeatId`，自动回退到「总体」 |

**数据迁移**：旧结构 `DepthGrid.cells`（无座位概念）→ 加载时被视作该深度下「最早位」（按当前 `seats` 数确定，如 9 人桌则是 `UTG`）的「总体范围」，其他英雄座位初始为空。同样地，更早的 `DepthGrid.seats[seatId]: Record<HandKey, Action>`（无对战概念）→ 加载时被视作该 (深度, 座位) 的「总体范围」，所有对战默认跟随总体。这样老数据不会被丢弃，也不会被错误地复制到所有位置 / 所有对战。

### 3.10 对战座位（Opponent）维度 + 总体（Overall）

**目的**：现实中同一手牌、同一深度、同一英雄位置，面对不同对战座位时打法可能不同（例如 BTN open 100bb 面对 SB 与面对 BB 的范围会有差别）。但大多数时候用户只想维护「不区分具体对战」的一张总体范围，仅在需要刻画差别时才单独拆分某个对战。因此引入「对战座位」维度，并配合默认的「总体」模式：

- **总体（默认）**：对战行**不渲染显式的「总体」按钮**。当 `currentOpponentId === null` 时即处于总体模式，此时对战行所有按钮均未高亮，左下方的 13×13 范围表显示并编辑该 (深度, 英雄座位) 的「总体范围」。
- **进入总体**：以下三种方式都会让 `currentOpponentId` 变为 `null`：
  1. 选择/切换英雄座位（英雄一变，对战自动重置为总体）；
  2. 再次点击当前已高亮的对战按钮（toggle 取消选中）；
  3. 新建/打开范围且历史 `lastOpenedOpponentId` 为空。
- **具体对战**：用户点击对战行里某个具体的对战座位（如英雄 BTN 时点 SB）→ 视图切到该 (深度, 英雄座位, 对战座位) 的独立范围；如果该对战之前从未被独立编辑过，**显示内容直接继承自总体**（视觉上与总体一致），但只是「跟随总体」而不是真的复制。

**Copy-on-Write（写时分叉）**：

- 跟随状态下，用户在网格上做的第一笔涂色会触发分叉：先把当前总体范围浅拷贝到该 (英雄, 对战) 的独立存储 `vs[opp]`，再把这一笔涂色应用到 `vs[opp]`。之后该对战与总体彻底独立，互不影响。
- 例外：编辑模式下用户在某个未独立的对战上点击颜色，但点击的颜色与该格当前显示一致（视觉上无变化），不会触发分叉，避免无意义地造出独立空表。
- `全部清空 / 全部 Raise / 全部 Call` 在「具体对战」上点击时同样按写时分叉处理：把对应的全 169 格写入 `vs[opp]`，使该对战立即独立化。

**取消编辑回滚**：进入编辑模式时会拍下当前 (深度, 英雄, 对战) 对应那张表的快照，并记录「该对战进入时是否已独立」(`wasIndependent`)。点 `✕ 取消` 时：

| 进入编辑时的状态 | 取消行为 |
|---|---|
| 总体（对战 = null） | 把快照写回该 (深度, 英雄) 的总体范围 |
| 具体对战，且当时已独立 | 把快照写回 `vs[opp]`，保持独立态 |
| 具体对战，且当时尚未独立 | 直接删除 `vs[opp]`，让该对战重新回到「跟随总体」状态（即使本次编辑已经触发了分叉也会被撤销） |

**对战行 UI**：

- 横排按钮位于英雄座位行下方一行；按钮集合 = 当前桌人数对应的座位序列中**剔除当前英雄座位**之后的所有座位 id。**不再渲染独立的「总体」按钮**，「总体」状态由对战行整行无高亮来表达。
- 已独立的对战按钮右上角带一颗小圆点，未独立（跟随总体）的对战按钮文字偏淡，让用户一眼看出哪些对战是「自定义过的」。
- 按钮 tooltip 显示该对战的全称、是否独立、命中数（独立 → 自身 `vs[opp]` 命中数；未独立 → 总体命中数，附「跟随总体」字样）。
- 用户在对战行已选中某个对战时，再次点击同一按钮 = toggle 取消选中，回到总体模式（`currentOpponentId = null`）。

**切换规则**（与 §3.8 编辑模式联动）：

| 触发 | 行为 |
|---|---|
| 在只读模式下点击某个对战按钮（与当前不同） | 切换 `currentOpponentId` 到该对战并写入 `lastOpenedOpponentId` |
| 在只读模式下再次点击当前已高亮的对战按钮 | `currentOpponentId` 置为 `null`（回到总体），同时写入 `lastOpenedOpponentId = null` |
| 在编辑模式下点击任意对战按钮 | 视同自动按「取消」处理（按上表逐情况回滚），再按上面两条规则执行对战切换 |
| 切换英雄座位 | `currentOpponentId` 自动重置为 `null`（总体）；对战是英雄的相对概念 |
| 切换深度 | `currentOpponentId` 保留不变；若新深度下该对战未独立，则显示成新深度的总体内容 |
| 修改桌子人数 | 若新座位序列不再包含 `currentOpponentId` 或它等于新英雄座位，自动重置为 `null` |

**数据持久化**：`PersistedState` 里新增 `lastOpenedOpponentId: string | null`，刷新页面会恢复上次激活的对战座位（包括「总体」状态 = `null`）。

## 4. 数据模型

```ts
type Action = 'fold' | 'call' | 'raise' | 'mixed';

type SeatId =
  | 'UTG' | 'U1' | 'U2' | 'LJ' | 'HJ'
  | 'CO'  | 'BTN' | 'SB' | 'BB';

/**
 * 一份 (深度, 英雄座位) 下的范围数据：
 *  - overall：总体范围（对战未指定时显示/编辑的那张表）
 *  - vs[oppId]：针对该对战座位的独立范围；未出现的对战表示「跟随总体」
 */
interface SeatBucket {
  overall: Record<string, Action>;
  vs: Record<string, Record<string, Action>>;
}

interface DepthGrid {
  label: string;                       // 深度标签，如 "100bb"，可自定义
  /**
   * 每个英雄座位 id 对应一个 SeatBucket。完全空的 (depth, seat) 不会出现在
   * 该字典里（运行时按缺省空对象处理，节省存储）。
   */
  seats: Record<string, SeatBucket>;
}

interface RangeDoc {
  id: string;            // uuid
  name: string;          // 用户命名，如 "BTN RFI"
  seats: number;         // 桌子人数（2–9），决定座位序列
  depths: DepthGrid[];   // 每个 range 自己的深度集合，数组顺序 = UI 显示顺序
  createdAt: number;     // 时间戳 ms
  updatedAt: number;
}

interface Storage {
  version: 2;
  defaultDepthLabels: string[];          // 新建 range 时的模板
  ranges: RangeDoc[];
  lastOpenedRangeId: string | null;
  lastOpenedDepthLabel: string | null;
  lastOpenedSeatId: string | null;       // 上次激活的英雄座位
  lastOpenedOpponentId: string | null;   // 上次激活的对战座位；null = 总体
}
```

### 4.1 单元格 key 生成规则
- 输入两张牌点数 `r1`, `r2`（按强度排序，强者在前）
- `r1 === r2` → `"AA"` / `"KK"` …
- 行号 < 列号（右上）→ `"${r1}${r2}s"`（同花）
- 行号 > 列号（左下）→ `"${r1}${r2}o"`（非同花）

牌点字符顺序常量：`['A','K','Q','J','T','9','8','7','6','5','4','3','2']`

### 4.2 标签唯一性
- 同一 range 内深度标签必须唯一（区分大小写敏感的字符串比较）
- 重命名/添加时若冲突 → 提示并阻止保存

### 4.3 数据迁移
- 若读取到 `nlh-range:v1`（旧扁平结构 `RangeDoc { stack, cells }`）→ 按 `stack` 字段把同名/同 id 的合并到新 `RangeDoc.depths` 中；旧 `cells` 视作该深度下「最早位」（9 人桌默认 UTG）的「总体范围」（即 `SeatBucket.overall`），所有对战默认跟随总体。
- 若读取到 `nlh-range:v2` 旧结构 `DepthGrid.cells`（无英雄座位维度）→ 加载阶段自动升级为新结构 `DepthGrid.seats`，把旧 `cells` 作为当前 `seats` 数对应序列的「最早位」的总体范围（如 6 人桌 → `UTG`，3 人桌 → `BTN`），其他英雄座位初始空。
- 若读取到 v2 但 `seats[seatId]` 仍是直接的 `Record<HandKey, Action>`（无对战概念）→ 自动包成 `{ overall: <旧cells>, vs: {} }`，所有对战默认跟随总体。
- MVP 阶段无 v1 数据，v1 迁移函数仅留占位；v2 内部升级在 `loadState` 的 sanitizer 中静默完成。

## 7. 关键交互细节

### 7.1 拖动涂色
- 在 `RangeGrid`（范围表组件）上监听 `pointerdown` / `pointerenter` / `pointerup`
- `pointerdown` 时记录 `isPainting=true` 与起始动作色
- `pointerenter` item 时若 `isPainting` 为真，则应用当前动作色到**当前激活深度**的范围表
- `pointerup` / 容器 `pointerleave` → `isPainting=false`

### 7.2 范围 / 深度 / 英雄座位 / 对战座位 切换
- 切换深度（点击 `DepthList` 中的 tab）：
  - 若处于编辑模式则先按「取消」回滚本次编辑，再切换
  - 切换后立即更新 `lastOpenedDepthLabel` 并重新渲染范围表；英雄座位与对战座位均**保持不变**
- 切换英雄座位（点击 `SeatTabs` 中的英雄行按钮）：
  - 编辑模式下先按「取消」回滚本次编辑，再切换 `lastOpenedSeatId`
  - 切换后**自动把对战座位重置回「总体」**（对战是英雄的相对概念）；同时写入 `lastOpenedOpponentId = null`
- 切换对战座位（点击 `SeatTabs` 中的对战行按钮）：
  - 编辑模式下先按「取消」回滚本次编辑（按 §3.10 的 `wasIndependent` 规则决定是否撤销分叉），再切换 `lastOpenedOpponentId`
  - 不切英雄、不切深度，仅渲染另一份对战表；未独立的对战表内容继承自总体
  - 再次点击当前已高亮的对战按钮 = toggle 取消选中，`lastOpenedOpponentId` 写为 `null`，整行无高亮 = 总体模式
- 切换范围（点击 `RangeList` 中的项）：
  - 若有未保存改动 → 弹确认
  - 切换后默认激活该范围 `depths[0]` 与 `lastOpenedSeatId`（若该 seatId 不在当前桌的座位序列里则回退到最早位）；`lastOpenedOpponentId` 同样按合法性回退（不在新序列里 / 等于英雄 → 回到「总体」）

### 7.3 新建范围
- 点 `+ 新建方案` → 弹窗输入名称（必填）+ 选择桌子人数（2–9，默认 9）
- 提交 → 用 `Storage.defaultDepthLabels` 复制生成 `depths`，每个 `seats` 字典初始化为空（即所有 (深度, 座位) 都默认 Fold）
- 立即激活新范围、其第一个深度，并把 `currentSeatId` 设为该桌人数对应序列的最早位

### 7.4 深度编辑（⚙ 编辑深度）
- 弹窗内列出当前范围的 `depths`（拖拽排序、内联改名、删除）
- 删除：弹二次确认（提示该深度的所有标记会丢失）
- 添加：底部输入框 + `+ 添加`，新深度的 `cells` 初始化为全 `fold`
- 重命名时校验同 range 内唯一性
- 底部勾选框「同时保存为新建范围的默认模板」
- 「应用」前所有修改是缓存态，「取消」直接丢弃

### 7.5 编辑模式切换（统计行的 `✎ 编辑 / ✓ 确定 / ✕ 取消`）

> 详细规则与按钮表格见 §3.8，这里只描述实现层面的事件序列。

- 进入编辑模式：
  - 仅在「已有激活范围 + 已有激活深度 + 已有激活座位」时按钮可点击
  - 点击后立刻把 `draft.depths[currentDepthLabel].seats[currentSeatId]` 做一次浅拷贝存为 `draft.editSnapshot`（含 `depthLabel` / `seatId` / `cells`）
  - `draft.editing = true`，UI 上 `✎ 编辑` 被替换为 `✓ 确定` + `✕ 取消`
- 编辑模式下涂色：
  - `RangeGrid` 的 `onPointerDown / onPointerEnter / onContextMenu` 检查 `draft.editing`，否则 early return
  - 涂色仍然走原有的 `rangeActions.paintCell(hand, action)`，正常写当前 (深度, 座位) 的 cells + 标 dirty
- 确定：
  - `draft.editing = false`，`draft.editSnapshot = null`
  - **不**触发持久化；dirty 标记按实际差异决定（如果本次编辑确实改动了 cells，则保留 `•`）
- 取消：
  - 把 `draft.editSnapshot.cells` 写回 `draft.depths[depthLabel].seats[seatId]`
  - `draft.editing = false`，`draft.editSnapshot = null`
  - 重新对比 draft 与 localStorage 中保存的版本，更新 dirty 标记（若本次编辑是唯一改动来源，dirty 应回到 false）
- 联动：
  - 切换深度 / 切换座位 / 切换范围 / 打开「⚙ 编辑深度」弹窗 → 内部先调用「取消」逻辑再执行原跳转
  - 点击顶部「保存 / 另存为 / 删除」→ 内部先调用「确定」逻辑再执行原操作

### 7.6 自动保存与显式保存
- 有"未保存修改"标识（顶部名称旁的 `•`）
- MVP 不做后台自动保存，避免覆盖意外操作
- "保存"会写入当前范围的全部 `depths`（不只是当前激活的深度子表）

### 7.7 统计
- Raise / 169、Call / 169、Fold / 169（基于**当前激活的 (深度, 英雄座位, 对战座位)** 子表；对战处于「总体」时统计的是 overall，处于具体对战且未独立时统计的是该对战所继承的 overall）
- 数字按百分比显示，1 位小数

## 8. 验收标准（MVP 完成定义）

1. 打开页面看到完整的范围表（13×13），所有 item 默认 **Fold（白底）**；左侧栏分上下两段；尚未新建范围时下段提示「先选择或新建一个范围」。
2. 点 `+ 新建` 输入 `BTN RFI` 保存 → 上段出现该项；下段自动出现 5 个深度 pill（`100bb / 60bb / 40bb / 30bb / 20bb`），默认激活第一个。
3. 选中 Raise，在 `100bb` 涂红若干 item → 切到 `60bb` 时范围表全为白底，确认数据互不干扰；切回 `100bb` 红色仍在。
4. 在 `⚙ 编辑深度` 里把 `60bb` 改名为 `50bb`、删除 `20bb`、新增 `8bb`，应用后下段 pill 列表与排序与编辑结果一致。
5. 输入名称 `CO RFI` 用 `+ 新建` 创建第二个范围 → 它的深度集合仍是默认模板（不受 `BTN RFI` 第 4 步修改影响），符合"每个 range 独立"的要求。
6. 在深度编辑弹窗勾选「同时保存为新建范围的默认模板」并应用 → 之后再 `+ 新建` 的范围会用更新后的模板。
7. 刷新页面：范围列表、各范围的深度集合、各深度子表内容全部一致；自动恢复到上次激活的范围与深度。
8. 删除某个范围后再刷新，确认已删除。
9. 底部统计与当前激活深度的实际涂色数字一致。
10. 在 1280×800 与 375×667（手机）两种尺寸下都可正常使用，移动端左侧栏可折叠。
11. 默认进入页面时统计行显示 `✎ 编辑` 单按钮，此时左键点格、左键拖动、右键单击均**不会**改变网格颜色；点击 `✎ 编辑` 后按钮变为 `✓ 确定` + `✕ 取消`，再涂色生效；点 `✕ 取消` 回到点击 `✎ 编辑` 前的网格状态；点 `✓ 确定` 保留涂色但**不**自动落盘（顶部仍显示未保存 `•`，仍需手动「保存」）；在编辑模式下切换深度或范围时本次编辑会被自动取消。

## 9. 后续可扩展（非 MVP）

- 跨范围/跨座位复制（把 A 的 `100bb · BTN` 复制为 B 的 `100bb · BTN`，或同 range 内 `BTN` → `CO` 复制）
- 范围对比（A.100bb.BTN ∩ B.100bb.BTN 高亮）
- 混合频率（每格分扇形显示比例）
- 场景标签（RFI / vs3bet / vs4bet / call vs RFI ...）
- 自定义座位标签 / 自定义座位序列（不强制使用截断规则）
- 导入 / 导出 JSON、PNG 图片
- 与 PIO / GTO+ 兼容的格式
- 简单 Equity 计算（蒙特卡洛 vs 范围）
- 云端同步（账户体系）
- 暗色 / 亮色主题切换、自定义动作颜色
- 全局深度模板的多套预设（如 「现金 6max」「MTT 巡回」分别一套默认）

## 10. 里程碑（MVP 实施步骤）

1. **脚手架**：Vite + React + TS 初始化，跑通空白页
2. **核心组件**：`hands.ts` 生成 169 key + `RangeGrid`（范围表）渲染 + 默认 Fold（白底）配色
3. **涂色交互**：`ActionToolbar` + 单击/拖动涂色 + 右键清除
4. **存储层**：`storage.ts` + `useRangeStore`（含 `defaultDepthLabels` 与按 range/depth 寻址的增删改查）
5. **左侧栏上段**：`RangeList` + `+ 新建`（自动用模板生成 depths）
6. **左侧栏下段**：`DepthList` + 切换深度联动范围表
7. **深度编辑弹窗**：`DepthEditorDialog`（拖拽排序、改名、增删、保存为默认模板）
8. **未保存提示与持久化恢复**：`lastOpenedRangeId` / `lastOpenedDepthLabel`
9. **统计与样式打磨**：`Stats` + 暗色主题 + 移动端左侧栏折叠
10. **手测验收**：按第 8 节逐条勾选
